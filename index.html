Where Agents Failed: Honest Analysis of Errors Found

1. Systematic MCP Undercounting

Both models originally missed that Fathom, HubSpot, Notion, Stripe, Linear, and Sentry all host official vendor MCP servers. Initial extraction marked them "No" or community-only. Cross-audit corrected all 6.

2. Perplexity False Negatives on APIs

Perplexity falsely classified Fathom, Pumble, Grain, and Consensus as "Blocked" because their documentation portals reside on sub-domains (api.fathom.ai, marketplace.cake.com). Verified active REST endpoints exist.

3. Gemini Hallucinations on Gating

Gemini claimed WhatsApp Business was instant self-serve (missing Meta's mandatory Business Verification) and extracted deprecated HAPIKEY for HubSpot (deprecated Nov 2022).

How the Research Agent Works

Multi-stage pipeline: automated extraction, adversarial cross-checking, and human sample reconciliation.

STAGE 01 Raw Extraction (60% Acc)

Automated Doc Crawl

The crawler scans public developer portals for API keys, OAuth endpoints, and quickstart guides.

Failure Mode: Often captures outdated syntax (e.g. deprecated HubSpot HAPIKEYs) or assumes sandbox access equates to production readiness.
STAGE 02 Cross-Audit (76% Acc)

Adversarial Verification

A secondary research agent cross-audits the findings, checking against real-world compliance gates, deprecation changelogs, and enterprise paywalls.

Result: Flagged 76 conflicting fields across the 100 apps, catching WhatsApp's Meta verification and PitchBook's $25k contract.
STAGE 03 Human Reconciliation

Human Hand-Check Loop

A human product ops reviewer manually opens live documentation for ambiguous edge cases to reconcile conflicting agent outputs.

Outcome: Restored Fathom, Pumble, and Grain to Ready after verifying live endpoints on subdomains.
